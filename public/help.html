01

Recommended

使用设备采集器持续上传

  1. 管理员创建设备

    在 Monitor 打开“设置 → 远端设备采集”，输入设备名称并点击“创建设备”。

  2. 立即保存一次性命令

    设备令牌只显示一次。每台设备单独创建，不要多人共用同一个令牌。

  3. 在远程电脑准备环境

    安装 Node.js 22 或更高版本，并用实际运行 Codex、拥有 ~/.codex 数据的系统用户操作。

  4. 下载并执行

    下载本页提供的 device-agent.js，在其所在目录运行管理员提供的完整命令。首次可追加 --once 做连通测试。

命令结构示例
node device-agent.js --url "MONITOR_URL" --user "数据用户ID" --device "设备ID" --token "一次性令牌" --once

测试成功会看到 accepted=...、duplicates=... 和 scanned=...。之后执行 node device-agent.js 即可保持每 15 分钟同步；配置和游标保存在 ~/.gpt-monitor/。

非默认 Codex 目录

指定数据目录
node device-agent.js --codex-home "/实际路径/.codex" --once
02

Operations

让采集器自动运行

首次带令牌命令运行成功后，令牌已经保存在当前用户目录。自启动命令不需要再次写入令牌。

Linux · systemd

服务用户必须与运行 Codex 的用户相同。

/etc/systemd/system/gpt-monitor-agent.service
[Unit]
Description=GPT Monitor Device Agent
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=你的Codex系统用户
WorkingDirectory=/opt/gpt-monitor-agent
ExecStart=/usr/bin/node /opt/gpt-monitor-agent/device-agent.js
Restart=always
RestartSec=15

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now gpt-monitor-agent
sudo systemctl status gpt-monitor-agent

Windows · 任务计划程序

  1. 选择“登录时”触发。
  2. 程序填写 node.exe。
  3. 参数填写采集器绝对路径，例如 C:\GPT-Monitor-Agent\device-agent.js。
  4. “起始于”填写采集器目录，并使用保存过令牌的同一 Windows 用户。
03

Snapshot

手动上传 SQLite 快照

  1. 找到数据库

    默认文件为 ~/.codex/state_5.sqlite，也可能由 Codex 配置中的 sqlite_home 指定。

  2. 打开用户数据设置

    在 Monitor 进入“设置 → 用户数据”，先选择正确的数据用户。

  3. 上传并刷新

    在“上传 SQLite”选择数据库，点击“上传并刷新”。

SQLite 上传会更新所选数据用户的完整快照来源，不会作为一台独立设备参与占比。多设备持续统计请使用设备采集器。

04

Privacy boundary

采集器上传什么

会上传

  • 设备 ID
  • 不可逆线程哈希和事件哈希
  • 事件时间、模型、提供方
  • 输入、缓存输入、输出、推理输出 Token
  • SQLite 线程总量快照

不会上传

  • 提示词和回复正文
  • 代码内容
  • 会话标题
  • 工作目录和文件路径
  • 浏览器登录密码或 Monitor Basic Auth
05

Diagnostics

常见问题

401 或令牌无效
令牌可能输入错误、已轮换或已吊销。管理员应为该设备轮换令牌，再运行新的接入命令。
设备显示“数据过期”
采集器超过 45 分钟没有成功同步。检查进程、自启动状态、HTTPS 地址和服务器网络。
首次同步时间很长
首次会流式扫描全部历史并分批上传，属于正常现象；后续只读取新增文件内容。
找不到 SQLite
使用运行 Codex 的同一系统用户，或通过 --codex-home 指定正确目录。
重复 Token
服务端按设备无关事件 ID 幂等去重；复制到其他设备的同一 rollout 不会重复计量。
