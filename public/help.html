01

Quick start

新设备快速接入

  1. 1
    添加设备

    进入“设置 → 远程设备”，填写一个容易识别的名称并点击“添加设备”。

  2. 2
    复制一键命令

    Windows 请选择“Windows PowerShell”并在 PowerShell 运行；Linux / macOS 在终端运行。必须使用运行 Codex 的同一系统账号，需要 Node.js 22 或更高版本。

  3. 3
    等待在线

    命令会完成下载、首次同步和自启动。历史很多时多等几分钟，设置页显示“接入成功 / 自动运行”后再关闭终端。

下载采集器保存安全配置首次同步配置自启动

接入命令只显示一次。命令中包含该设备的专用令牌，请直接发给对应设备的使用者，不要发到群聊或公开工单。遗失时在设备卡片点“重新接入”即可生成新令牌，旧令牌会立即失效。

02

Required update

已有设备升级到 Agent 2.1.1

修复安装 · Agent 2.1.1

重新运行设置页生成的一键命令

  1. 1

    在 Monitor 打开“设置 → 远程设备”，找到已有设备，点击“重新接入”。

  2. 2

    选择远端系统，复制新的一键安装命令；旧令牌会立即失效。

  3. 3

    在原设备、原系统用户下运行命令，等待首次同步完成。设置页会显示采集器版本和最近同步结果。

Why one full rescan?

补齐 Fork 血缘信息

从 2.0 或更早版本升级时会完整重扫一次历史，用于补齐父线程哈希和累计 Token 状态；已经完成 2.1 血缘重扫的设备会保留现有游标。

重扫是幂等的，不会把同一事件重复计量。完成后继续按文件偏移增量读取，每 15 分钟同步一次，不会反复扫描全部历史。

不要复制或手工修改令牌。每台设备都应使用自己设备卡生成的命令。升级、换机或怀疑令牌泄露时，都使用“重新接入”生成新命令。

03

Daily operations

安装成功后通常无需操作

先确认设备卡显示“同步正常 / 自动运行”。下面的维护命令只在一键安装成功后可用，安装程序会自动创建 ~/.gpt-monitor/device-agent.js。如果该文件不存在，请回到“设置 → 远程设备”点击“继续安装”，不要继续运行 --once。

自动

持续更新

采集器每 15 分钟增量同步；失败后会按 1、5、15 分钟自动重试。连续 45 分钟没有成功同步时，Monitor 会提示数据过期。

检查

查看本机状态

不会显示设备令牌。

Windows PowerShell
node (Join-Path $HOME '.gpt-monitor\device-agent.js') --status
Linux / macOS
node "$HOME/.gpt-monitor/device-agent.js" --status
立即

手动同步一次

无需等待下一次自动同步。

Windows PowerShell
node (Join-Path $HOME '.gpt-monitor\device-agent.js') --once
Linux / macOS
node "$HOME/.gpt-monitor/device-agent.js" --once
更新

升级或重新安装

在设备卡点击“重新接入”，再运行新命令。它会更新采集器、令牌和自启动配置，不需要先卸载。

移除

卸载自启动

保留本地配置；追加 --purge 可同时删除配置与游标。

Windows PowerShell
node (Join-Path $HOME '.gpt-monitor\device-agent.js') --uninstall
Linux / macOS
node "$HOME/.gpt-monitor/device-agent.js" --uninstall
特殊目录、Linux 注销后运行和手动方式

Codex 数据不在默认目录

在首次接入命令末尾增加 --codex-home "/实际路径/.codex"。必须使用实际运行 Codex 的同一系统用户执行。

Linux 用户退出后也要继续同步

采集器默认安装为当前用户的 systemd 服务。如果服务器未开启用户 linger，可由管理员运行：

sudo loginctl enable-linger "$USER"

只做一次 SQLite 快照

可在“设置 → 用户数据”上传 ~/.codex/state_5.sqlite。它适合临时快照，但不会作为独立设备参与设备占比；长期统计请使用采集器。

下载采集器源码仅用于审查或完全手动安装。这个网页下载地址与远端安装后的 ~/.gpt-monitor/device-agent.js 是两回事；常规接入会自动下载并创建本地文件。

04

Token accounting

费用、日趋势与 Fork 净用量

Monitor 按事件拆分未缓存输入、缓存输入和输出，并先扣除 Fork 继承的共享历史。日报、设备占比与 API 等价成本因此统一使用分叉后真正新增的净用量。

01 · 原始原始 Token

SQLite 与 telemetry 记录的线程累计总量，尚未处理继承历史。

−
02 · 扣除共享历史

父线程与 Fork 完全一致的累计状态前缀，不属于新分支的新增消耗。

=
03 · 计入净 Token

原始 Token 减去共享历史；仪表盘的趋势、设备占比和成本统一使用该值。

在哪里核对

在消耗仪表盘的“数据审计”区域查看原始 Token、已扣除共享历史、净 Token和 Fork 线程数。三者应满足：净值 = 原始值 − 扣除值。

分叉后的新消耗会保留

仅扣除父子线程完全一致的历史前缀。Fork 之后产生的新累计状态仍归入实际发生日期和对应设备，不会整条会话忽略。

什么时候费用是确定值

所选范围的未缓存输入、缓存输入、输出均已拆分，且模型、日期与长上下文倍率都有价格时，面板显示“确定值”。推理输出包含在输出内，不会重复计费。

什么时候仍显示估算

缺少 rollout 拆分或模型价格时，只有缺口会进入混合估算、区间或未定价。拆分覆盖率和已定价覆盖率可说明原因；金额始终是 API 等价成本，不是 ChatGPT 套餐账单。

日趋势如何读

亮色实线是所选范围合计，多设备时每台设备再绘制一条虚线。可切换总 Token、未缓存输入、缓存输入、输出和成本；所有曲线、刻度与摘要使用同一纵轴口径。

设备归属如何确定

升级时保留已有本机归属；之后新事件固定归给中心首次观察到它的设备。复制同一 rollout 不会改变既有设备占比，跨设备继续产生的新状态则归新设备。

人工审批 Fork：确认排除、保留计入与恢复规则

进入“设置 → Fork 审批”。推荐保留“辅助审批”：显式父会话连续匹配至少 2 个累计状态时自动排除；只有 1 个共同状态或仅由精确前缀推断出的关系先保留计入，等待人工确认。子会话从父会话中段开始也能识别；没有共同状态、缺少父记录或存在循环关系时不会猜测扣除。

  1. 1

    先核对父子会话、候选共享 Token、连续状态数、父事件偏移和分支净新增量。

  2. 2

    确认是继承历史时点“确认排除”；认为是独立消耗或证据不足时点“保留计入”。后者会把此前已经排除的 Token 加回。

  3. 3

    要撤销人工决定时点“恢复规则”，该关系会重新按当前审批模式判断。每次操作都会重算趋势、设备占比和费用。

“高置信自动应用”会让精确前缀推断也自动排除；人工决定始终优先。审批只使用线程关系和累计 Token 状态，不读取提示词、回复或代码正文。

日量仍异常高时：先确认所有远端设备均为 Agent 2.1.1 且已完成一次完整同步，再刷新用量缓存；随后对照数据审计区的原始、扣除与净值，并在“设置 → Fork 审批”处理待审批关系。

05

Privacy boundary

只同步用量，不同步内容

会上传

  • 设备 ID、采集器版本、操作系统和同步状态
  • 不可逆线程哈希、父线程哈希与事件哈希
  • 事件时间、模型和提供方
  • 输入、缓存输入、输出、推理输出及累计 Token 状态
  • SQLite 线程 Token 总量快照

不会上传

  • 提示词和回复正文
  • 代码内容
  • 会话标题
  • 工作目录和文件路径
  • Monitor 登录密码或浏览器凭据
06

Diagnostics

遇到问题先看这里

提示找不到 device-agent.js

说明一键安装尚未完成，或命令在另一个系统用户下执行。请使用运行 Codex 的同一用户打开 Monitor 的“设置 → 远程设备”，点击该设备的“继续安装”，复制对应系统的一键命令重新运行；不要手工猜路径。

设备仍显示 Agent 2.0 或更早版本

不能只运行 --once 更新程序。请在 Monitor 的设备卡点击“重新接入”，复制并运行新命令；看到 Agent 2.1.1 且首次完整同步完成后才算升级成功。

提示需要 Node.js 22

在远程电脑安装 Node.js 22 或更高版本，关闭并重新打开终端，再运行原接入命令。用 node --version 可检查版本。

设备一直显示“等待首次同步”

确认命令在运行 Codex 的同一系统用户下执行，并检查远程电脑能否访问上方的 Monitor 地址。首次历史较多时请等待几分钟。

设备显示“数据过期”

在远程电脑运行上面的“查看本机状态”和“手动同步一次”。若返回 401，请在 Monitor 对该设备执行“重新接入”，再运行新命令。

更换电脑或令牌泄露

在设备卡片点击“重新接入”。新命令生成后旧令牌立即失效；在新电脑运行新命令即可。

重复复制了同一份 Codex 历史

服务端会按与设备无关的事件 ID 幂等去重，同一个 rollout 出现在多台设备时不会重复计量。

Fork 后某一天的用量仍然很高

先在“数据审计”核对共享历史扣除量。如果远端设备尚未升级，请先更新至 Agent 2.1.1 并等待完整同步结束；随后在首页刷新用量，再进入“设置 → Fork 审批”查看待审批关系。确认是继承历史时选择“确认排除”，证据不足时选择“保留计入”，处理后确认净 Token 与趋势已重新计算。
